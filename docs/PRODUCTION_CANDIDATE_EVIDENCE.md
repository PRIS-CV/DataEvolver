# Registered training evidence and confined candidate execution

`ProductionCandidateTrustContext` and `ProductionContextRunner` use the explicit
`registered_production_runtime` namespace. Synthetic qualification contexts are
inadmissible. Only public signing material crosses the existing chroot, dropped
credentials and seccomp boundary; candidate code is never imported by the host.

`FrozenTrainingObservationAuthority` reopens the original frozen Controller and
verifies the committed registered surface observation, exact Gateway output and
receipt. It cannot execute a Controller, recover a provider or mutate evidence.
The original training trial authority supplies the source, rejected candidate,
immutable masks, references, actual support, crop and frozen settings.

`compile_training_evidence` maps those artifacts into the candidate's declared
pure JSON ABI. It does not infer geometry or classifications. Required outer
boundary envelopes may include apertures; only immutable silhouette pixels get
a boundary witness. Registered effects retain their surface membership checks.
Protected and uncertain coverage never becomes edit permission. The finite set
projection preserves all intersections that can affect candidate support; the
original evidence hashes, projection counts and exact crop remain recorded.
Structural reading of unsupported observations leaves their original status and
the ordinary execution validator's rejection intact.

`evolution.execute_training_candidate:1` executes one predeclared diagnostic
through the existing Controller, with the exact source, input and context hashes
in its durable child record. Completed effects are recovered without execution;
an intent without a durable result remains ambiguous. CPU/output bounds and all
prior usage are explicit. It adds no model, Planner or image authority.

The diagnostic does not pass production qualification, reactivate a revoked
version, submit an image or create an accepted dataset record. A safe refusal is
useful negative evidence only. Production qualification still requires the
original independent source families and matched checks, actual permitted
operation/request/native bindings, fixed quality checks, runtime visual review
and independent loading. Different sandbox limits must be declared explicitly;
they cannot be described as a matched method comparison.
## Registered diagnostic feedback

`evolution.inspect_training_candidate_feedback:1` reopens one committed
production diagnostic using its own frozen source and original effect verifier.
It verifies the exact child streams, registered input, candidate package, native
origins and lifecycle usage. It never repeats the child or converts the
synthetic qualifier's feedback into production evidence. Missing results,
changed bytes and nonterminal Controllers block the reader.

The versioned feedback contains the actual refusal status, per-reason row counts
(which may overlap), original request, source/protocol/receipt hashes and the
projection's explicit lack of new authority. Large raster lists and untrusted
candidate prose remain in the exact original artifacts. Safe refusal establishes
neither an algorithm defect nor positive production quality.

`ProductionFeedbackReviewDomain` binds that view and an explicit one-call
text-only admission before freeze. Prior usage and the original resource deadline
must agree with the verified diagnostic. Through the same RuntimeRSIPlanner and
EvolutionController, the system may request a general capability or abstain.
Neither choice revises source, probes geometry, grants editing authority,
qualifies a candidate or submits an image. Any later operation requires its own
frozen authorization and unchanged quality gates.

## Evidence sufficiency requested by runtime

`evolution.inspect_evidence_sufficiency:1` consumes the actual committed runtime
artifact-contract request. Its read-only authority reopens the original review
with the original Planner/Gateway contracts, verifies the diagnostic bootstrap,
request event, exact model receipt and native output/events, and dispatches no
calls. Candidate diagnostic rows retain their original JSON pointers and hashes.

The CPU check intersects only the explicit declared coverage and preservation
sets already present in the authenticated input. It emits counts and hashes,
never coordinates or permissions. A conflict in these supplied sets leaves real
task feasibility indeterminate; uncertain boundary envelopes may explain a
conflict without proving the task impossible. Evidence-type declarations list
provenance requirements and stay DECLARED / NOT_ASSESSED. They cannot satisfy a
missing witness. This refusal-diagnostic version produces conflicting,
evidence-insufficient or indeterminate receipts; positive production sufficiency
requires separately qualified witnesses and is not implemented by this reader.

## Native boundary evidence probes

`data.probe_instance_boundaries:1` exposes the existing resident SAM3 API through
a bounded runtime observation. Runtime RSI chooses selected IDs, descriptions
and normalized boxes from actual source/reference media. Original target IDs,
thresholds, masks, source and seed stay bound. Identical completed subject
queries are rejected before inference. No fallback, hole filling or mask edits
are applied to native output.

The same ModelGateway owns one segmentation request and a separately captured
runtime visual inspection. The original training resource admission supplies
two stable observations with the original deadline. Native masks are independently
decoded and compared with immutable masks; these differences establish neither
aperture truth nor effect ownership. Visual uncertainty remains uncertainty.
Every result stays OBSERVED_UNQUALIFIED and blocks generation/adoption. This
probe obtains new evidence, not production qualification. Incomplete stages
reconcile existing exact receipts or remain ambiguous; they are never resent.

Resident startup must retain the SAM loader report alongside the original
processor/video/detector objects. `adapters.resident_components` validates this
contract without loading or moving models. A legacy resident missing this
metadata cannot be repaired through a health/inference-only RPC API. Preparing
a corrected bootstrap does not modify the active process. Deployment must obey
the user's restart/reload authorization; debugger injection and fabricated
loading reports are not a compatibility mechanism.

### Known pre-forward probe failure

`FrozenBoundaryFailureAuthority` reopens the failed probe with its own frozen
framework and verifies replay, the real Planner receipt, pending action, SAM
request/native failure and failed Gateway cost. It accepts only the exact
missing-component failure before the worker's first model call, with no output,
partial masks, visual review or unknown duration. It performs no provider call.

`BoundaryProbeRecoveryDomain` transfers that unchanged decision into a new
frozen Controller. The failed SAM reservation remains spent; a separate bounded
admission supplies one new SAM attempt and the unused visual-review allowance.
No new Planner decision, editing permission or quality acceptance is implied.
The original resource deadline and instance mapping remain bound. The old run,
failed request ID, native files, snapshot and events are never restarted or
rewritten. Repairing a resident requires the deployment authorization applicable
to that service, independently of admitting this recovery.

SAM startup retains the real loader report with the original detector object.
`loading_report_json` converts actual set inventories to deterministic JSON
arrays for status serialization without changing the in-memory report, filling
missing metadata, loading weights or mutating a live service.

### Registered feedback from a completed native probe

`FrozenBoundaryFeedbackAuthority` reconstructs the completed recovered probe
under that run's own source and checks its original Controller, frozen contract,
events, native masks, visual-review receipt and failed-attempt accounting. A
read-only audit guard forbids new dispatch or file mutation. Local visual
support and rejected apertures are retained as observations, with no editing,
effect attribution, production qualification or adoption permission.

`evolution.inspect_boundary_probe_feedback:1` captures that authenticated view
through the same Controller. A separately bounded, text-only runtime review can
then choose the next general capability or abstain. Its new model allowance and
all prior failed costs are explicit; it cannot silently repeat a segmentation,
repair a task, reset a resource deadline or treat a proposal as qualified.

### Boundary witness artifact

`evolution.capture_boundary_witness:1` implements an actual runtime artifact
request. The closed `dataevolver.boundary_witness.v1` schema binds the original
source, constraints, immutable instance correspondence, original local scope,
native segmentation and independent visual receipts. Each assessment retains
its exact report pointer, row hash and original reason; mask comparisons remain
separate observations. Selected instances outside that probe stay unassessed.

The CPU compiler and validator emit no new pixel labels. Object, background,
uncertain pixel evidence and effect ownership remain `NOT_ASSESSED` when the
registered observations supply no qualified pixel witness. A conformant artifact
can therefore report `INSUFFICIENT_EVIDENCE`, including actual preservation
conflicts and missing native receipts. Altered source, scope, correspondence,
findings or provenance is `INVALID_EVIDENCE`. Neither status diagnoses an
algorithm defect or grants editing, qualification, promotion or adoption.

The operator uses the existing Controller and frozen authorities, checks the
complete original artifact closure on recovery, and performs no model, probe,
candidate or production execution. Operational qualification still requires
the original independent process and budgets. Contract conformance alone
establishes no production quality, method gain or downstream training gain.

### Independent operational evidence qualification

`evolution.qualify_boundary_evidence:1` consumes the completed witness through
its frozen reader and a separate actual runtime operator request. It evaluates
boundary coverage, visible apertures, background preservation and effect
ownership for each immutable selected instance. It performs no model or probe
execution and supplies no new pixels or editing authority.

Additional evidence enters only through `RegisteredBoundaryQualificationEvidence`,
which reuses both actual `ControllerProductionQualificationAuthority` stages and
their frozen production execution. Host-owned `quality_checks` role manifests
must bind each predeclared family and every consumed pixel/effect artifact in
the committed verifier closure. Other source families can qualify a method;
they cannot label the current source. Synthetic authority fixtures, package
reports, immutable masks and native proposals cannot supply this port.

The typed `dataevolver.boundary_operational_evidence.v1` record binds source,
original constraints, correspondence, witness and full required subject scope.
Partial evidence remains unresolved. Conflicting independent findings remain
unresolved. A prior rejected or uncertain assessment needs an explicit,
independently verified resolution reference; the original observation remains
in the result. Missing production authority or evidence produces
`INSUFFICIENT_EVIDENCE`. A scoped `SUPPORTED` evidence result still grants no
submission, adoption, whole-task completion or dataset quality acceptance.

Pure compiler positive fixtures test these semantics only. Actual positive
production qualification requires independently obtained evidence satisfying
the existing frozen validation process, including source isolation and costs.

## Completed evidence acquisition

`evolution.acquire_independent_evidence:1` imports already produced evidence
through `RegisteredIndependentEvidenceProvider`. It has no inference, network,
provider discovery or scheduling backend. Its provider is the existing exact
`RegisteredBoundaryQualificationEvidence` reader with both original production
Controller stage authorities. Missing providers return explicit prerequisites
for every original subject/claim and leave the original qualifier insufficient.

The committed host `native_audit` role manifest must bind each current-source
claim record to a typed provider provenance record, the actual execution and
trust-profile digests, original scope and receipt. The host verifier, external
to the candidate, establishes the provider's scoped authority and independence.
The importer checks that binding and complete closure; an `independent` flag in
caller JSON creates no authority. Dependent/unassessed claims are not imported;
prior masks/assessments cannot supply independent production receipts. Pixel
agreement and effect ownership require distinct evidence. Original conflicting
findings still need explicit independent resolution in the unchanged qualifier.

The acquisition receipt contains the qualifier's result and provider gaps.
It grants no pixels, editing rights, submission, adoption or promotion. A
successful empty-provider diagnostic demonstrates the import boundary only.
It does not create the missing provider or establish production quality.
Further provider development must use the existing isolated candidate package
and independent production qualification lifecycle, with a bounded stopping
rule; another import wrapper is not progress toward the missing evidence.

`FrozenProductionFeedbackReviewAuthority` also reads a terminal runtime
`ABSTAIN` through its own frozen Controller, original trace, Gateway receipt
and native closure. It performs no recovery execution or inference, and cannot
manufacture an implementation request. The strict capability request authority
continues to reject abstention. A launcher postcheck failure is recorded
separately from an already committed runtime decision and its model cost.
