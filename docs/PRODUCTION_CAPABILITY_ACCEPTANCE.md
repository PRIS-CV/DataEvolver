# DataEvolver：正式使用能力与可验证自进化验收

本文件记录 2026-10-18 用户明确的产品目标：达到 DataFlow 和 DataFlow-MM 可以在正式场景使用的数据处理能力，并在 Harness 中形成可验证的自进化能力与算子。它是验收规格，不是已经达到目标的声明。现有数据交付仍须完成；单个样本只作为回归案例。

## 对标依据

2026-10-18 核对的官方入口：

- [DataFlow](https://github.com/OpenDCAI/DataFlow)：生成、精炼、评估、过滤与可组合算子；官方说明已包括动态组合与创建算子的 Agent。
- [DataFlow-MM 官方文档](https://opendcai.github.io/DataFlow-MM-Doc/en/mm_guide/intro/basicinfo/intro/)：图像描述、视觉问答、区域描述、生成与编辑；视频描述、切片、过滤与问答；音频问答、语音活动切分、识别与清洗。
- [DataFlow-Harness](https://github.com/OpenDCAI/DataFlow-WebUI)：现有 skills、MCP 与可视化工作流，支持 coding agent 构建流水线。

上述资料说明对方公开的功能范围；没有在本项目部署或测评这些第三方实现。不能用“有 Agent”“能创建算子”作为本项目已经超越它们的证据。新增目标是有独立证据的改进、晋升、复用与撤回。

## 当前实现与正式验收矩阵

当前实现定位到本仓库的公开模块。仅出现文件或通过 fixture 不表示正式可用；真实证据应另绑定冻结协议、来源、执行回执和独立产物。

| 能力 | 当前源码入口与证据边界 | 正式使用的验收条件 |
| --- | --- | --- |
| 数据接入与存储 | `dataset/contracts.py`、`harness/task_contracts.py` 的 Intent/ArtifactRef 与来源绑定；当前重点为图像 | 声明支持的文本/文档/图像/视频/音频格式；有效与损坏输入、许可及来源缺失均有确定结果；内容哈希和独立读取通过 |
| 基础算子 | `dataset/curation.py`、`curation_quality.py` 有审计、家族、拆分、选择、清洗、评分与导出实现 | 每个宣称可用的算子有版本化输入输出、参数、前置条件、资源和错误语义；在独立真实来源上运行，无任务脚本修补 |
| 模型与多模态算子 | `adapters/model_gateway.py` 与既有生成/评审/分割接入；整个多模态矩阵尚未完成统一验收 | 文本/文档、图像、视频、音频分别有正式端到端样例和质量协议；缺失的模态保持未验收；复用第三方算子仍经同一 Gateway 与合同 |

| 生产执行与恢复 | `controller.py`、`state_store.py`、Operator execute/recover/verify_effect 与原生请求账本 | 真实中断/进程重启/部分写入/未知外部效果的恢复证据；有界批量、吞吐和峰值资源实测；未知结果先对账 |
| 质量与交付 | 冻结 Evaluator、训练域固定模型检查、运行时媒体审核及 portable delivery | 每种任务预声明质量指标与保护条件；原始检查记录、拒绝理由、完整闭包和搬移后独立加载均通过；训练收益另行验证 |
| 配方 R 改进 | `runtime_rsi.py` 与领域 compiler 支持真实运行时提案和比较；已有真实回退，不能据此称改进成功 | 同源、同模型/种子/评价下，实际操作发生变化且质量采用；保护指标不过线不得采用 |
| 经验 K 生命周期 | `training_workflow.py` 实现候选、独立验证、晋升快照与后续采用检查；完整实际闭环未通过 | 独立新来源验证通过，冻结 K ID/版本/兼容范围；后续真实提案和请求使用该 K，并记录结果；读取快照不算使用 |
| 算子与 Harness 演化 | `capability_requests.py` 记录系统能力请求；当前实现阶段仍由开发 Agent 承担 | 由注册开发/验证算子产出隔离候选包，按下述协议资格审查；新冻结合同采用，旧运行不热修改；后续真实使用及回归撤回均留证 |
| 方法 M 改进 | 训练域当前拒绝将 R 补丁标成 M；没有独立 M 收益证明 | 在同 R/K 起点、来源池、模型/评价和在线预算下比较旧/新方法，核算开发成本；独立多源与保护指标通过后才可作范围内结论 |

矩阵按已声明能力逐项验收。小型样例、源码数量、算子数量或页面展示不能单独证明与 DataFlow 系列达到同等正式使用能力。

## 算子职责与合同

基础算子直接处理或检查数据：接入、解码、规范化、去重、拆分、筛选、标注、生成、转换、质量检查及导出。模型调用不是演化权限。每个注册条目应提供：身份与实现摘要、命名输入输出及 schema、参数 schema、支持模态、确定性/副作用类别、模型角色与资源上限、写入边界、超时/成本、恢复方法、效果核验与局限。

进化算子处理改进对象：诊断失败、提出 R、蒸馏 K、提出新算子/合同/方法、构建候选、安排独立验证、形成资格证明、晋升/撤回。输出是有界提案、候选包或证据；不得自行修改 Evaluator、预算、生产注册表或已冻结代码。是否执行和是否采用仍由唯一 EvolutionController 与冻结规则控制。

K 是有来源、适用域和版本的经验制品；M 是产生提案、搜索或学习的方法。基础算子版本升级是候选实现变化，不自动代表 M 改进。开发 Agent 实现通用接口属于辅助开发；若系统尚不能自行完成候选构建与资格验证，报告必须保留这一依赖。

## 候选开发、独立验证与采用协议

以下是待补齐的通用协议，不表示这些生命周期状态已全部接通：

1. REQUESTED：提交运行时原始能力请求和证据摘要；保留原失败与不确定性。
2. SPECIFIED：冻结通用输入输出、禁止变更、验收协议、预声明开发/独立验证/最终保留来源及总预算；给同类请求设停止条件，不能逐次续段制造进展。
3. IMPLEMENTED_CANDIDATE：注册开发算子只写隔离候选根，输出代码/合同/依赖清单及可追溯 diff。模型、凭据、生产目录、旧媒体和最终评价集不可作为实现捷径。
4. ENGINEERING_VERIFIED：验证 schema、保护不变量、幂等/恢复、反例、资源/费用及可搬移性；不将这些结果计为质量收益。
5. INDEPENDENTLY_QUALIFIED：按预声明新来源，匹配输入池、R/K 起点、模型、评价与在线预算比较；包含成功、失败和不支持用例。单源回归不得晋升通用能力。
6. CANARY_ACCEPTED / PROMOTED：冻结 Evaluator 通过后，保存候选包和资格证明、兼容范围及版本；只在后续新冻结合同中激活。已运行快照保持原样。
7. REUSED：证明后续兼容任务实际加载该版本，产生可核对的操作/请求及产物，记录质量和成本。
8. SUSPENDED / RETIRED：回归或兼容性失效时，追加撤回事件并阻止后续选择，返回已验证版本；旧账本与历史采用证明不删除。

开发、验证与晋升作为同一 Controller 的注册动作推进，不引入平行队列控制面。实现者可收到开发证据，独立评价来源与最终留出集不能用来逐图给答案。能力范围不明确、独立验证不可执行、资源/预算不可用或同类请求连续无进展时，形成有证据的能力阻塞；不重复同源同参数请求。

## 立即执行顺序

1. 将现有注册算子整理为带合同与证据等级的能力清单，并冻结正式使用验收矩阵。先复用现有 data/model 节点、执行接口和第三方适配边界。
2. 在现有 REQUEST_CAPABILITY 与 Controller 之间补齐“候选包 → 工程资格 → 独立资格 → 新合同采用/撤回”的通用开发协议。当前图像边界权限请求只作为该协议的一个回归案例，禁止围绕该案例继续无限添加专用入口。
3. 按既有协议继续系统提出的算子回归、K 独立验证与真实复用、原数据主批与独立包；按已授权顺序完成视频交付。再按明确模态范围补齐文本/文档、图像、视频、音频的正式端到端验收。

当前硬件、模型、资源截止、历史费用、质量门和数据交付合同继续有效。上述规格不授权替换模型、延长既有截止或使用额外 GPU。具体任务内容不得交给外部架构顾问；其建议只作为框架工程输入，不能替代实际证据。
