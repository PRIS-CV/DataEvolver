# 数据工作区

可选的 Workbench 新增收集、清洗、审核与导出三个页签。页面使用已有的 Harness Controller 和图像流水线，调度与质量门槛沿用原有实现。

## 准备执行主机

按[图像流水线指南](../IMAGE_DATA_PIPELINES.md)准备收集 Goal 或清洗 Goal。Goal 包含带哈希的合同，以及对来源、模型、策略和证据输入的不可变引用。页面接收当前执行主机上的 Goal 文件路径，不编辑这些输入，也不生成新 Goal。

在工作台设置中选择本机或 OpenSSH 执行目标及 Python 环境。在本机路径或远端执行设置中填写**绝对数据集目录**。查看器中的交付包路径相对于该目录。每次读取会核对当前标签页展示的主机和路径配置。其他标签页修改配置后，应刷新 Workbench 再次读取。本机目录和 SSH 目录分别配置，页面不执行同步。

在执行主机设置 Goal 中各 store 对应的环境变量，以及模型端点和密钥变量。本机命令继承 Workbench 进程环境。SSH 命令使用远端命令环境；需要加载部署环境时，可将 `remotePython` 配置为加载环境并转发参数的主机端解释器脚本。Workbench 不复制本机密钥或数据到远端。标注和审核模型使用流水线的 ModelProfile 角色绑定，独立于图像工坊的生成与编辑接口。

## 收集与清洗

1. 在收集或清洗页填入已有 Goal 路径，点击**预检计划**。页面通过已有任务 API 提交 `plan --goal`。该命令离线预检，不下载数据、不推理，也不创建 Campaign。
2. 阅读回执。store 变量齐全时，收集计划展示解析后的来源配置。清洗计划展示解析后的质量策略。计划还会报告节点、预算、缺失的 store 变量和阻塞项。进程成功退出时，计划仍可能处于阻塞状态。
3. 填写 Campaign 根目录和明确的幂等键。创建 fixture 图像 Goal 时启用 **Fixture Goal（--dry-run）**，server Goal 应关闭。点击**从 Goal 创建**。Campaign ID 由原生 Goal 决定；后续控制应填写同一个 ID。
4. 使用**有界推进、状态、解释、回放、暂停、恢复执行**。推进和恢复会执行任务。暂停沿用原生检查点语义，不代表运行中的远端 worker 已立即停止。

回执保留任务输入、状态和有界日志尾部。页面刷新当前排队或运行中的回执。执行效果未知时，状态仍为 unknown；重试前应核对原生回执。任务继续使用已有的有界队列。`plan` 与状态查询一样绕过执行队列。候选子会话的桥接权限仍限于 status/explain/replay。

## 审核与导出

填写含 `bundle.json` 或 `dataset.json` 的相对目录。**交付包摘要**展示 SourceBundle 或清洗包的元数据，包括已有的成员引用和下载信息。**读取样本**支持清洗导出的 `manifest.jsonl`、`quarantine.jsonl` 和 `reviews.jsonl`。每页最多读取 20 条完整记录，通过字节游标翻页，不在浏览器加载 Parquet。

选择记录后，可查看 caption、归一化框、完整标注、质量门槛和审核证据。隔离记录可能只有原因，没有图像。查看器只显示列于包元数据中的导出图像。解析后的图像路径应位于包目录内，图像字节应与成员 SHA-256 一致。

页面读取已有导出，不创建压缩包、不改写记录，也不授予训练就绪状态。元数据和 JSONL 按原记录展示，查看器不独立验证整个交付包。完整校验仍使用已有的原生 loader。`mock_verified`、`layout_ready`、`technical_candidate_pending_independent_review` 和 `training_candidate` 保留原有含义，均不能证明训练收益。

标准库读取器沿用 Harness 任务的本机或 SSH 目标及 Python 选择。读取上限为：元数据 4 MiB、单条 JSONL 512 KiB、每页表数据约 4 MiB、单图 8 MiB、进程输出 16 MiB、超时 30 秒。超限或格式错误会报错，不会把截断记录当作有效证据。翻页期间请勿替换交付包；替换后应从首页重新读取。

本次接入不包含来源与策略表单生成器、人工标注修改、压缩包下载或流水线专用节点仪表盘。通用 Harness 页仍可查看完整命令回执。
